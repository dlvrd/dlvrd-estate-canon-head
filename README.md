# `dlvrd-estate-canon-head`

**This repository contains one commit hash.** It is the current `HEAD` of the
private governance repository `dlvrd-estate-canon`, republished on every change.

    HEAD.txt     the 40-character commit hash
    HEAD.date    the commit date of that hash, ISO-8601

## What it is for

Consumers of the estate's governed documents — `reporting.md`,
`relay-hygiene.md`, `NOMENCLATURE.md`, `glossary.md` — need to know **when those
documents have moved.** Canon is private, and a CI job's `GITHUB_TOKEN` is
minted per run and scoped to the repository its workflow lives in; it cannot be
widened to a second private repository. So a CI job cannot read canon, and until
this repository existed the only alternatives were a long-lived read credential
in every consumer's secrets, or no coverage at all.

**A commit hash discloses nothing.** It is not reversible, it names no file, no
version and no content, and the objects it identifies stay private. So the
credential moves from several consumers reading *into* the governed repository
to one producer writing *out of* it — and the next consumer costs nothing: no
grant, no secret, no onboarding.

## How to use it

    curl -s https://raw.githubusercontent.com/dlvrd/dlvrd-estate-canon-head/main/HEAD.txt

Record that value. Compare it on every build. **When it differs, canon has
changed** — read `VERSIONS` in canon itself to learn *what* changed, and adopt
the moved files before re-recording.

**Re-recording the hash without reading what moved satisfies the check and
defeats its purpose.** It detects change; only you can detect relevance. That
sentence is `dlvrd-parcel`'s, from the failure message of the first consumer to
build against this.

## THE FAILURE MODE, STATED AS A PROPERTY RATHER THAN A CAVEAT

**If the publishing workflow breaks, this mirror stops moving — and a frozen
mirror is indistinguishable from a canon that has not changed.** Every consumer
would read *unchanged*, and every consumer would be wrong. That is the estate's
oldest failure shape wearing the fix's clothes, and it is not papered over here.

**Two things follow, and the second is the point.**

`HEAD.date` is published beside the hash so a consumer *may* flag an implausible
age. It is a courtesy and it is not the control — a heuristic about staleness is
a guess.

**The control is that the breakage is visible to the producer and invisible to
consumers.** A failed workflow run is unmissable in the private repository's
Actions tab, and nothing about this repository's contents would announce it. So
the single point of quiet failure sits with the only party who can see it, which
is the correct place for it — but it does mean **a consumer must not treat a
matching hash as proof that canon is unchanged. It is proof that the mirror is
unchanged.**

## Provenance

Proposed by `dlvrd-parcel` on 2026-08-27, after building the consumer-side check
and finding that it could not run in CI for any remote participant. The
structural argument — *the credential moves from several consumers to one
producer* — is theirs, as is the refusal to substitute a timestamp heuristic for
an honest statement of the failure mode.

Published by `governance-runner`. Nothing here is generated by hand: the hash is
written by a workflow in canon on every push.
